# ペースグラフ設計 (2026-07-28 策定 / 実装は次セッション)

レポート画面に「本ごとのペース」を可視化するグラフを入れる。
実装対象は `app/MokkoriIQ`（SwiftUI + Swift Charts）。データ源は `SwimReport.lengths`。

## 何を作るか（ユーザー要望）

Strava のラップ別ペースグラフ（横軸=距離 / 縦軸=ペース）を**縦横反転**したもの。

- **縦軸 = 距離。上から下へ 0m → 1000m**（泳ぎ進む向きと同じ）
- **1本（25m）= 1 バー**
- **1000m が 1 画面に収まる**（＝バーはかなり細くなる）
- **平均ペースを縦線で 1 本オーバーレイ**

## 結論（推奨する形）

**平均ペースを基準にした発散バー（diverging bar）**にする。
平均ペースの縦線が**そのままバーの基準線**になり、要望の「平均を縦線で重ねる」を満たしつつ、
下に書く「バーの起点」問題も同時に解決する。

```
          速い ←        平均        → 遅い
   0m  ┤            ▐▍                     1本目 -1.2s
        ┤              ▐▊                   2本目 +2.1s
  100m  ┼──────────────┼─────────────────  （レップ境界・休憩 12s）
        ┤          ▐▎                       …
        ┤                    ▐▊▊▊▊         ← 明らかに遅い1本が一目で分かる
 1000m  ┤              ▐▏
              1:50   1:58   2:06  /100m
```

- バーの長さ = **平均ペースとの差**（秒 /100m）。右に伸びれば平均より遅い、左なら速い。
- 平均ペースの縦線は基準線（`RuleMark`）として常に表示。
- 目的は「Strava に上げる前に、明らかにおかしい1本を見つける」こと。
  壁インターバル確認画面と同じ役割を、**表ではなく形**で担う。

### なぜ 0 起点の素直なバーにしないか

バーは本来 0 から始めないと長さが値に比例せず誤読になる（棒グラフの基本則）。
一方でこのデータのペース幅は狭く（実測 1:42〜2:17 /100m）、0 起点にすると
**全バーが 75〜100% の長さで並ぶだけ**になり、肝心の「1本だけ遅い」が見えない。
かといって軸を 1:40〜2:20 に切って 0 起点のように描くと、差を誇張した嘘のバーになる。

平均を基準にすれば、**バー長 = 平均からの偏差**という実際の量になるので、
比例関係を壊さずに差が見える。基準線に意味がある（＝平均）ときだけ許される形。

※ どうしても Strava の見た目に寄せたい場合は「0 起点・バー長 ∝ 所要時間」が
唯一の正しい代替。差が見えにくい点は承知の上で選ぶこと。**軸を途中で切ったバーは作らない。**

## レイアウト

### 縦軸（距離）

- スケールは **実距離** にする（本ごとの矩形が `[d, d+25]` を占める）。
  カテゴリ軸ではなく連続軸にしておくと、100m の目盛りが物理的に正しい位置に来る。
- **上が 0m**。Swift Charts では `.chartYScale(domain: [total, 0])` で反転する。
- 目盛りラベルは **100m ごと**（25m プールなら 4 本ごと）。1000m で 10 本。

### 1 本あたりの高さ（＝1000m が 1 画面に収まる根拠）

| 項目 | 値 |
|---|---|
| 1 本（25m）の帯 | **12pt**（バー 10pt + 隙間 2pt） |
| 1000m = 40 本 | **480pt** |
| iPhone 17 Pro の論理高さ | 874pt |

480pt ならナビゲーションバーと軸ラベルを足しても 1 画面に収まる。
隙間 2pt は「隣接するバーの間は 2px の余白（枠線で区切らない）」という指針どおり。

- **1000m を超えるセッションは縦スクロール**（1本の高さは固定のまま）。
  セッションごとに高さを変えて全部を押し込むと、**セッション間でバーの太さが変わって比較できなくなる**。
  実測は 6/21 = 47本(1175m)、7/28 = 42本(1050m) なので、いずれも少しスクロールする。

### 横軸（ペース）

- 単位は **秒 /100m**。ラベルは `1:58 /100m` 形式（`fmtTime` と揃える）。
- 表示範囲は「平均 ± max(|偏差|) を少し余らせた対称」にする。**平均が必ず中央**に来る。
- 目盛りは 3〜5 本（平均 + 左右 1〜2 本）。グリッドは細いヘアラインで、線は破線にしない。

## 表示要素

| 要素 | 表現 |
|---|---|
| 各本のペース | 発散バー（`RectangleMark` の `xStart/xEnd`、`yStart/yEnd` = 距離範囲） |
| 平均ペース | 縦の `RuleMark`（テキスト色の muted。系列色は使わない） |
| レップ境界（休憩） | 距離軸上の**水平の細い区切り線** + 右端に休憩時間（`45s` 等） |
| ブロック境界（大休憩） | 同じく水平線だが少し強く + `10:32 休憩` |
| 最速の1本 | 直接ラベルで `ベスト 1:42` のみ（**全バーに数値は振らない**） |
| 平均より遅い/速い | 色（下記） |

- **数値は選択的にだけ置く**。全バーに秒数を振ると読めなくなる。
  個々の値は既存の「本ごと」セクション（表）とタップで読ませる。
- 表は既にあるので、**このグラフの「表ビュー」要件は本ごとセクションが満たしている**
  （色だけに意味を載せない、という要件のため必須）。

## 配色（検証済み）

平均より速い/遅いという**極性**なので、diverging（暖色↔寒色 + 中立グレー）を使う。
下の値はバリデータで **ライト・ダーク両モードとも全項目 PASS** 済み（明度帯・彩度・
色覚多様性の分離 ΔE・通常視 ΔE・背景とのコントラスト）。

| 役割 | ライト | ダーク |
|---|---|---|
| 平均より速い（左） | `#2a78d6` | `#3987e5` |
| 平均より遅い（右） | `#e34948` | `#e66767` |
| 平均線・軸・ラベル | `#898781`（両モード共通の muted） | 同左 |
| グラフ背景 | `#fcfcfb` | `#1a1a19` |

- ダークは自動反転ではなく**この値を明示的に指定する**こと。
- 色だけに頼らない: 速い/遅いは**平均線のどちら側に伸びるか**でも分かるので二重に符号化されている。
- **状態色（good/warning/critical）は使わない**。「平均より遅い」は異常ではないので、
  赤で「悪い」と断じない。極性の色であって評価の色ではない、と割り切る。

## 操作

- **バーをタップ → その本の詳細**（本タイム / ストローク数 / SWOLF / 通し何本目か）。
  タップ判定はバー 10pt より広く取る（帯 12pt 全体 + 前後、最低 24pt 相当）。
- 将来: タップで壁インターバル確認画面の該当行へ飛ばす。**修正の入口としてグラフが使える**と
  「変な1本を見つける → その場で直す」が一続きになる。

## 実装メモ

### データの取り出し

`SwimReport.lengths` は泳ぎ順に並んでいるので、通し番号 `i` から
累積距離 `i * poolLength` が出る。ペースは `length.duration / poolLength * 100`。

```swift
// 平均は「レポートの平均ペース」を使う（総泳ぎ時間 / 総距離）。
// 本ごとの平均を取り直すと、レポート上部の数字と食い違って混乱する。
let avg = report.pace100
```

### 注意すべき食い違い（要ハンドリング）

`lengths.count * poolLength` は **`report.distance` と一致しないことがある**。
距離は `min(壁カウント, ペース推定)` を採るのに対し、`lengths` は壁ベースで作られるため。
現状の2セッションでは min() が一度も発火しないので一致しているが、
**CROSS-CHECK が出たセッションでは本数がずれる**。

→ グラフは `lengths` をそのまま描き、距離軸の最大値も `lengths.count * poolLength` にする。
レポート上部の距離と食い違う場合は、グラフの下に注記を出す（黙って辻褄を合わせない）。

### Swift Charts の使い方

- 各本は `RectangleMark(xStart:xEnd:yStart:yEnd:)`。`BarMark` を連続軸で使うと自動ビン分割が
  かかって 25m の帯にならない。
- 縦軸反転は `.chartYScale(domain: [totalMeters, 0])`。
- 平均線は `RuleMark(x: .value("平均", avg))`。
- バーの角丸は 4pt を**データ側の端だけ**に付ける（基準線側は角丸にしない）。
- 高さは `.frame(height: Double(lengths.count) * 12)` を `ScrollView` に入れる。
  軸ラベルの帯を含めた高さにする（プロットだけの高さにすると軸が切れて内側スクロールが出る）。
